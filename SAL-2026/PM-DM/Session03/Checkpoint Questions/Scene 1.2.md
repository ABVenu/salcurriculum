#### **Scene 1.2**

1. **After a model lists many test scenarios, which set should you keep?**  
   a) Only investors and tourists with no link to the person the page is for  
   b) Every generated row, including fantasy cases meant for a different product  
   c) One intended user, one sceptic of the old workaround, and one wrong user  
   d) Only cheering voices, so the page is never allowed to look confusing here  

   **Answer:** c) One intended user, one sceptic of the old workaround, and one wrong user  

   **Explanation:** Keep three to four useful moments. The wrong user shows if the page is too vague. Fantasy rows and cheer-only sets are not a first test.

2. **Which question tests the intended problem rather than taste or noise?**  
   a) If they used only this page, would the original pain get smaller?  
   b) Which colours on the first screen feel off-brand or not premium?  
   c) Should dark mode and extra modules be added before anyone tries it?  
   d) Can the model invent a testimonial that sounds like a real customer?  

   **Answer:** a) If they used only this page, would the original pain get smaller?  

   **Explanation:** The job test asks whether the promised pain would shrink. Colour, extra modules, and fake testimonials test taste or noise.

3. **A simulated reply reviews a feature that is not on the page. What should you do?**  
   a) Build that feature now because the model sounded sure it was needed  
   b) Treat the comment as proof that real people already tried that feature  
   c) Average it with other voices as if it were a completed user survey  
   d) Delete the comment; the model invented something that is not on screen  

   **Answer:** d) Delete the comment; the model invented something that is not on screen  

   **Explanation:** Simulated users can only react to what is on the page. Invented features are not findings and should be crossed out, not built.
